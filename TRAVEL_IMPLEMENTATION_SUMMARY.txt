🎯 IMPLEMENTOWANA LOGIKA
═══════════════════════════════════════════════════════════════════════════════

✅ TEMPO PODRÓŻY
   • Ostrożne (Sz/2)     → 2 pkt zmęczenia/km
   • Normalne (Sz)       → 4 pkt zmęczenia/km
   • Biegiem (2×Sz)      → 12 pkt zmęczenia/km (blokada na nieznanym)

✅ MODYFIKATORY BIOMÓW (5 km dystans)
   Na drodze:           ×0.8 (20% szybciej)
   Bez drogi:
   • Łąka               ×1.0 (baza)
   • Las                ×1.5 (50% wolniej)
   • Skały              ×2.0 (100% wolniej)
   • Bagno              ×3.0 (200% wolniej)
   • Jezioro            ❌ NIEMOŻLIWE bez drogi

✅ ODKRYWANIE TERENU
   Jeśli nieznany kafelek:
   • +2.0 godziny (rekonesans)
   • +15 pkt zmęczenia (stres)
   • Blokada biegiem (przełączenie na normalne)

✅ WPŁYW WYTRZYMAŁOŚCI
   Modifier = 1.1 - (Wytrzymałość × 0.01)
   Przykład: Wyt=10 → modifier=1.0, Wyt=20 → modifier=0.9 (10% redukcja)

📊 PRZYKŁADOWE WYNIKI
═══════════════════════════════════════════════════════════════════════════════

SCENARIUSZ 1: Normalne tempo, łąka odkryta, brak drogi
  Hero: Sz=10, Wt=12
  ├─ Czas: 5km / 10km/h × 1.0 = 30 min
  ├─ Zmęczenie: 5 × 4 × 0.88 = 17.6 ≈ 18 pkt
  └─ REZULTAT: 30 min, +18 zmęczenia

SCENARIUSZ 2: Ostrożnie, las nieznany, brak drogi
  Hero: Sz=10, Wt=12
  ├─ Czas: 5km / 5km/h × 1.5 + 2h (odkrycie) = 210 min (3h 30min)
  ├─ Zmęczenie: 5 × 2 × 0.88 + 15 (odkrycie) = 24 pkt
  └─ REZULTAT: 3h 30min, +24 zmęczenia

SCENARIUSZ 3: Biegiem, skały odkryte, brak drogi
  Hero: Sz=10, Wt=12
  ├─ Czas: 5km / 20km/h × 2.0 = 30 min
  ├─ Zmęczenie: 5 × 12 × 0.88 = 52.8 ≈ 53 pkt
  └─ REZULTAT: 30 min, +53 zmęczenia

SCENARIUSZ 4: Normalne, las, Z DROGĄ
  Hero: Sz=10, Wt=12
  ├─ Czas: 5km / 10km/h × 0.8 (droga) = 24 min
  ├─ Zmęczenie: 5 × 4 × 0.88 = 18 pkt (bez kar biomu!)
  └─ REZULTAT: 24 min, +18 zmęczenia (droga zaoszczędza czas!)

STRUKTURA:

@Serializable
enum class TravelPace(
    val displayName: String,
    val speedMultiplier: Float,
    val fatiguePerKm: Float
) {
    CAUTIOUS("Ostrożne", 0.5f, 2f),
    NORMAL("Normalne", 1.0f, 4f),
    RUNNING("Biegiem", 2.0f, 12f)
}

@Serializable
data class TravelResult(
    val pace: TravelPace,
    val distanceKm: Float = 5f,
    val biome: TravelBiome,
    val isOnRoad: Boolean,
    val isDiscovered: Boolean,
    val travelTimeHours: Float,
    val travelTimeMinutes: Int,
    val fatigueGained: Int,
    val messageLog: String
)

object TravelMechanics {
    fun calculateTravelTile(
        heroData: String,
        pace: TravelPace,
        targetCell: TravelMapCell,
        isDiscovered: Boolean,
        isOnRoad: Boolean
    ): TravelResult { ... }
    
    fun applyTravelToProgress(
        currentProgress: HeroProgress,
        travelResult: TravelResult,
        readFromFile: (String) -> String
    ): HeroProgress { ... }
}

3 GŁÓWNE ZMIANY W HeroTravelMapScreen:

1. DODAJ STAN
   var selectedTravelPace by remember { mutableStateOf(TravelPace.NORMAL) }
   var showTravelSummary by remember { mutableStateOf(false) }
   var lastTravelResult by remember { mutableStateOf<TravelResult?>(null) }

2. DODAJ UI (3 przyciski tempa)
   Row(...) {
       TravelPace.values().forEach { pace ->
           Button(onClick = { selectedTravelPace = pace }) { ... }
       }
   }

3. ZMODYFIKUJ moveTo()
   val travelResult = TravelMechanic.calculateTravelTile(
       heroData = readFromFile("hero_$heroId"),
       pace = selectedTravelPace,
       targetCell = cell,
       isDiscovered = ...,
       isOnRoad = ...
   )
   
   val updatedProgress = TravelMechanic.applyTravelToProgress(
       currentProgress = heroProgress,
       travelResult = travelResult,
       readFromFile = ::readFromFile
   )
   
   persist(updatedMap, updatedProgress)

4. POKAŻ WYNIK (AlertDialog)
   if (showTravelSummary && lastTravelResult != null) {
       AlertDialog(text = { Text(lastTravelResult!!.messageLog) })
   }
